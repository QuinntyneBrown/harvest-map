# L2 - Detailed Requirements

Source of truth: `docs/mocks/` (page `pages/<id>/<state>.html`, dialog `dialogs/<id>/<state>.html`, notification `notifications/<id>/<state>.html`). Routes come from `docs/mocks/manifest.json`. Every acceptance test file shall begin with a header comment `// Traces to: L2-xxx` naming the L2 requirements it covers.

---

## L2-001: Sign in
**Traces to:** L1-001

Route `/sign-in`. Fields: E-mail, Password. Links: "Forgot password?". Button: "Continue". Mocks: `pages/sign-in/*`.

**Acceptance Criteria:**
1. Given the sign-in page, when it loads, then it shows "Harvest Map is invite-only.", E-mail and Password fields, "Forgot password?" and "Continue".
2. Given both fields are empty, when the user submits, then an error summary "Fix 2 things to save" lists "Enter the e-mail address you were invited with" and "Enter your password", each field shows its inline message, and focus moves to the summary.
3. Given the summary is shown, when the user activates an item, then focus moves to the matching field.
4. Given valid credentials, when the user submits, then the button shows a busy state, repeat submits are ignored, and on success the user lands on the Field home page (`/`).
5. Given the service is unreachable, when the user submits, then the alert "Can't reach Harvest Map — Check your connection, then try again." appears with a "Retry" action and entered values are kept.

## L2-002: Forgot password
**Traces to:** L1-001

Route `/forgot-password`. Mocks: `pages/forgot-password/*`.

**Acceptance Criteria:**
1. Given an invalid or empty e-mail, when the user submits, then an inline message "Enter an e-mail address like name@example.com" is shown and no request is sent.
2. Given any well-formed e-mail (registered or not), when the user submits, then the page shows "Check your inbox" and "We sent a reset link to {e-mail}. It works for 30 minutes.".
3. Given the success state, when it appears, then "Resend" is disabled with a 60 s countdown ("Resend in 58 s") and enables at zero; "Back to sign in" returns to `/sign-in`.
4. Given the request fails, when the user submits, then an error alert with retry is shown and the e-mail is kept.

## L2-003: Reset password
**Traces to:** L1-001

Route `/reset-password` (token in link). Fields: New password, Confirm password. Mocks: `pages/reset-password/*`.

**Acceptance Criteria:**
1. Given a reset link, when the page opens, then a loading state is shown while the token is checked.
2. Given a password shorter than 12 characters or a mismatched confirmation, when the user submits, then "Fix 2 things to save" lists "Use at least 12 characters" and/or "Passwords don't match".
3. Given a valid token and valid passwords, when the user submits, then the password is updated, and the success state links to sign in.
4. Given an expired, used or malformed token, when the page opens, then the error state explains the link no longer works and links to `/forgot-password`.

## L2-005: Field home page
**Traces to:** L1-002

Route `/`. Mocks: `pages/field/*`.

**Acceptance Criteria:**
1. Given the catalogue has data, when the page loads, then it shows the headline "The field is ripe.", counts of organizations, people and problems, the count of research runs since yesterday, and actions "Ask the web" (opens Run research) and "See the map" (`/map`).

## L2-006: Organizations list
**Traces to:** L1-003

Route `/organizations`. Mocks: `pages/organizations/*`.

**Acceptance Criteria:**
1. Given organizations exist, when the page loads, then the header shows "{n} tracked · {v} verified · {u} unverified" and each card shows mark, name, "Type · City · Reach", tags and a Verified or Unverified status.
2. Given the filter chips AI, Youth, Moonshot, Verified, when the user toggles chips, then only organizations matching all active chips are listed and the active chips are shown as pressed.
3. Given the Sort control with Impact, Name, Updated, when the user picks an option, then the list reorders accordingly (default Impact).
4. Given the search box, when the user types, then the list filters by name after 150 ms of idle typing.
5. Given a filter or search matches nothing, when the list renders, then the no-results state offers to clear filters.
6. Given there are no organizations, when the page loads, then the empty state offers "New" and "Import".
7. Given loading or load failure, when the page renders, then a skeleton list or an error with "Retry" is shown respectively.
8. Given names that are very long, right-to-left or non-Latin, or a missing mark, when rendered, then text wraps without hiding information, direction is preserved, and an empty mark tile shows rather than a broken image. A record whose sources disagree shows a "Conflict" status.
9. Given the user checks one or more cards (checkboxes appear on hover, focus, always on touch), when selection is non-empty, then a bar shows "{n} selected" with "Tag", "Export {n}" and "Archive".

## L2-024: Review findings

7. Given the dialog request fails, when it returns, then the failed state shows with retry; the dialog scrolls inside when its content exceeds the viewport height.
