Theming

Light and dark from one token file; OS preference by default, forced with data-theme.

WCAG 2.2 AAStatus: stableSince v1.0
  • Overview
  • Token tiers
  • Adding a theme
  • tokens.json
  • Do and don't
  • Tokens

Overview

  • Light on :root; dark on [data-theme="dark"] and under prefers-color-scheme: dark unless forced light.
  • color-scheme set per theme so native controls follow.
  • prefers-contrast: more strengthens borders and muted text; forced-colors hands rings to system colours.

Token tiers

TierExampleWho reads it
Primitive--palette-ember-700Semantic tokens only
Semantic--color-accentComponents and pages
Component--btn-bgOne component

Adding a theme

Copy the dark block, rename it, change semantic tokens only, add pairs to contrast-pairs.json, run the checker.

tokens.json

tokens/tokens.json is the DTCG export (aliases as {group.token}, dark under $extensions). Regenerate with tokens_to_json.py.

Do and don't

  • Do override semantic tokens in a theme.
  • Don't write colours in components.
  • Don't invert light to get dark: build dark from roles.
