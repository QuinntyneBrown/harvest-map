Forms

One column in a 44rem card; validate on submit, then on input; summary first.

WCAG 2.2 AAStatus: stableSince v1.0

Overview

Create and edit pages for organisations, people and problems share one form shape.

When to use

  • Page form for records; dialog form for one to three fields (Add person).
  • Destructive confirmation needs the typed name.

Structure

Live composition.
HTML
<form class="card stack" style="max-width:28rem;gap:var(--space-6);" novalidate><div class="field"><label class="field__label" for="pf-n">Name</label><input class="input" id="pf-n" value="FaithTech"></div><div class="field"><label class="field__label" for="pf-w">Website</label><input class="input" id="pf-w" type="url" value="faithtech.com"></div><div class="form-actions"><button class="btn btn--ghost" type="button">Cancel</button><button class="btn btn--primary" type="button">Save</button></div></form>

States

  • Default · Invalid (summary + inline) · Submitting (busy, read-only) · Success (Saved · just now) · Unsaved changes dialog on leave.

Responsive

  • Grids of short fields collapse to one column under 640px.

Accessibility

  • Focus to summary on failed submit; aria-invalid + aria-describedby.

Content

  • Labels nouns; errors instructions.
